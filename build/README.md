# Building Slipstream (packaging)

This folder holds the packaging/build infrastructure for a standalone
Windows desktop build. It does not affect running Slipstream from source
(`python main.py gui`, `python gui_main.py`) in any way.

## Prerequisites

- Windows 10/11
- A Python 3.11/3.12 virtual environment, activated
- Runtime + build dependencies installed:

  ```powershell
  pip install -r requirements.txt -r requirements-gui.txt -r requirements-build.txt
  ```

ANSYS is **not** required to build or run the packaged executable — the
GUI's mock mode works standalone, exactly as it does from source.

## Scripts

| Script | What it does |
|---|---|
| `build\clean.ps1` | Removes all generated packaging output (`dist\`, `.pyinstaller_cache\`, `release\`, `build\version_info.txt`). Never touches anything under version control. |
| `build\build.ps1` | Generates the Windows version resource from `cfdauto.__version__`, then runs PyInstaller against `build\slipstream.spec`, producing a one-folder build at `dist\Slipstream\Slipstream.exe`. |
| `build\release.ps1` | Runs `clean.ps1` + `build.ps1`, then zips the result into `release\Slipstream-v<version>-win64.zip`, where `<version>` is read live from `cfdauto.__version__` — never hand-typed. |

Run any script from the repository root (they resolve their own paths, so
`cd`-ing into `build\` first isn't required):

```powershell
powershell -ExecutionPolicy Bypass -File build\build.ps1
```

## Why one-folder, not one-file

`build/slipstream.spec` deliberately produces a one-folder build (a
`Slipstream\` directory containing `Slipstream.exe` plus its DLLs), not a
single-file executable. PySide6/Qt is LGPLv3-licensed; one-folder mode
keeps Qt's DLLs as separate, individually replaceable files rather than
unpacking them into a hidden temp directory at runtime — the same
LGPL-compliance approach already called out in
[`docs/CFD_PLATFORM_BLUEPRINT.md`](../docs/CFD_PLATFORM_BLUEPRINT.md) §20.
Don't change this to a one-file build without revisiting that note.

## Version metadata

The executable's file/product version (visible in the `.exe`'s Windows
Properties ▸ Details tab) is generated by `build\make_version_info.py`
from `cfdauto.__version__` — the single authoritative version source for
the whole application (window title, status bar, About dialog, and now
packaging metadata all read from it). `build\version_info.txt` is
regenerated on every build and is not committed.

## Icon

No icon asset exists in this repository yet, so the packaged executable
uses PyInstaller's default icon — this sprint deliberately does not invent
branding. To add one later, drop a `.ico` file at
`gui/resources/slipstream.ico`; `build/slipstream.spec` picks it up
automatically with no other changes needed.

## Known limitations

- Windows-only. The engine and GUI both run cross-platform from source,
  but this packaging path (PyInstaller `.spec`, `.ps1` scripts) targets
  Windows specifically, matching ANSYS's primary supported platform.
- No installer (MSI/NSIS) — the release archive is a plain zip of the
  one-folder build. A user unzips it and runs `Slipstream.exe` directly.
- Not code-signed. Windows SmartScreen may warn on first launch of an
  unsigned executable; this is expected and unrelated to the build itself.
- Packaging has not been exercised in this sprint against a real ANSYS
  install — only the mock-mode GUI path is covered by the automated test
  suite. See `docs/RELEASE_CHECKLIST.md` for the manual verification a
  release should still go through.
