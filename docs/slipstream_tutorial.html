NEO v2.2 GUIDE

Slipstream wraps the cfdauto CFD automation engine in a professional desktop interface. You define a parametric study in Excel, press Run All, and watch every simulation from geometry update to convergence — live, in one window.

Overview

Everything you could previously only see in the terminal is now visualised in real time. The engine is identical — same Workbench journal, same PyFluent pipeline, same Excel resume ledger — the GUI simply makes it observable and interactive.

Sidebar, Queue & docks

The Sidebar holds the brand header, the Workspace navigation (Dashboard / Results / Charts / Images), and the Project section with the project tree. The Queue is a persistent right-hand panel, not a dock — hide it with the ☰ toggle in the workspace header. Monitor and Parameters are docks that are hidden by default — reveal them from View → Monitor / Parameters. The bottom Log · Statistics · Console group is a tabbed dock; drag any dock by its title bar to move or tab it. Use View → Reset layout to restore the default arrangement.

💡 Tip — what "converged" means

The engine uses force flatness, not residuals. It checks that CL and CD change by less than a threshold over the last 50 samples. You'll see Converged at iteration N in the Log when it stops early — this is correct behaviour.

To capture actual pressure/velocity contours from Fluent, open config\config.yaml and set fluent.capture_images: true. This triggers an experimental step after convergence. If it fails for any reason, the case still completes normally.

Open View → Parameters (the dock is hidden by default). Click any row in the Queue first to load it.

⚠ Lock rule

Inputs can only be edited on rows that have not produced results yet (status PENDING, FAILED, or SKIP). Rows with status DONE show their values as read-only to protect provenance.

Resume and retry

Resume after a stop or crash

Slipstream is always resume-safe. Close the window, kill the terminal, or press Stop — the experiments.xlsx Status column records exactly where you are. Re-open the app and press ▶ Run All: DONE rows are skipped, the batch continues from the first PENDING row.

💡 Tip

Any row left as RUNNING by a crash is automatically re-queued on the next run. You never lose progress.

Retry failed rows

1

Tick ☑ Retry FAILED in the Queue

2

Click ▶ Run All

Failed rows are added back to the queue and re-executed.

Re-run everything from scratch

Select all rows in the Queue (Ctrl+A), right-click → Re-queue (clear status), then click ▶ Run All.

Or regenerate a clean schedule from the terminal:

python main.py init-template experiments.xlsx

Then click Reload Project in the toolbar.

Troubleshooting

Nothing to do — all rows say DONE

The workbook already has results from a previous run. Right-click rows → Re-queue, or tick Retry FAILED if rows are FAILED.

Window opened but charts/plots are blank

Add useOpenGL=False to pyqtgraph config. Open gui\theme.py, find pg.setConfigOptions(...) and add the option, then restart.

Run All does nothing (engine exits instantly)

Check the Log panel — it will show the reason. Most common: ANSYS project file not found (wrong path in config.yaml), or Workbench GUI is open at the same time.

Row stuck as RUNNING after a crash

This is expected and handled automatically. Re-run the app and press ▶ Run All — the RUNNING row is re-queued and starts fresh.

Excel save fails / workbook locked

Close experiments.xlsx in Excel. The engine retries 10 times (60 seconds) — if you close Excel during that window, the save succeeds.

Workbench crashes (rc=3221225477)

Close the Workbench GUI before running. Only one Workbench instance can have a project open at a time. Check the runs\cases\<id>\wb_stdout.log file for the actual error (visible in the Project section of the sidebar → double-click the file).

CL is negative / L/D chart goes downward

This is the rotation sign issue: the P1 parameter is rotating the wing nose-down for positive values. Fix: in DesignModeler, open the Rotate body operation and flip the rotation axis direction. Re-export baseline.cas.h5 and re-run.

Fluent crashes with "Abnormal Exit" / RPC handshake failure

Usually an ANSYS Student license lockout after previous crashes. The Student license only allows 1 concurrent Fluent session — if a prior session didn't exit cleanly, its license tokens remain "stuck" for 30–60 minutes.

Fix: Kill orphaned processes, wait 5 minutes, then retry:

Get-Process | Where-Object {$_.ProcessName -like "*fluent*"} | Stop-Process -Force
Get-Process | Where-Object {$_.ProcessName -like "*fl_mpi*"} | Stop-Process -Force
# Wait 5 minutes for license server to release tokens
Remove-Item -Force runs\cfdauto.lock -ErrorAction SilentlyContinue
python main.py run --retry-failed --config config/config.yaml

Mesh image shows only smooth surface (no grid lines visible)

Fluent 26.1's mesh display API doesn't always set edge visibility properly through the settings tree. The latest fluent_controller.py uses TUI commands as a fallback to force edge display. If grid lines still don't appear:

1. Enable save_case_data: true in config, then open final.cas.h5 in Fluent GUI for full 3D mesh inspection.

2. Inspect runs\cases\<id>\case.log for lines like Could not capture mesh.png — the log shows which graphics API path failed.

Solver stalls at high AOA (CL/CD frozen for 1500 iterations)

Steady-state RANS cannot resolve deep post-stall flow (typically past ±14° AOA). The solver "converges" numerically but the physics is unphysical due to massive vortex shedding that RANS artificially damps. Limit AOA range to ±12° for meaningful results. Beyond that requires LES/DES (not feasible on Student edition due to compute limits).

⚠ Signs of a stalled solve

CL/CD values change by less than 0.001 across 500+ iterations, but residuals never drop below ~1e-3. The solver is stuck, not converged. Reduce max_iterations to 500 and set accept_unconverged: true to save time.

compute() returned no value warning

Cosmetic warning on Fluent 26.1 — the report_definitions.compute() API returns an empty list on this version. Results are extracted from the history file correctly. The latest fluent_controller.py uses the history file first and eliminates this warning entirely.

Images not appearing after real ANSYS runs

Verify capture_images: true is set under the fluent: section in config (NOT under ansys:):

@"
import yaml
cfg = yaml.safe_load(open('config/config.yaml'))
print('capture_images =', cfg['fluent'].get('capture_images', False))
"@ | python

Must print capture_images = True. If it shows False, the line is either missing or placed under the wrong YAML section.

Mock mode doesn't activate (no orange banner)

YAML is case-sensitive: use mock: true (lowercase), not mock: True. Also ensure the line is indented under runtime:, not at the top level. After changing the config, click Reload Project (Ctrl+R) or restart the app.
